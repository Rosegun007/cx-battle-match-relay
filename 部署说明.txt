CX对战 Cloudflare 联机握手转发服务器 S0007

本包需与客户端 S0007-0001-1 配套使用。旧 S0006 服务端不支持本轮协议。
本文件是部署说明；本轮没有替你部署线上 Worker。

包内结构：
  src/index.js      Worker 与 Durable Object 完整源码
  wrangler.jsonc   沿用原 Worker 名称、绑定和迁移配置
  package.json     npm 部署命令

部署步骤：
1. 保留此前 S0006 服务端 ZIP 作为回退备份。
2. 解压本包，进入包含 package.json 和 wrangler.jsonc 的目录。
3. 在你原先部署此 Worker 的环境中，使用原 Cloudflare 账户。
4. 安装依赖：npm install
5. 部署：npm run deploy
6. 打开该 Worker 的根地址，返回 JSON 应包含：
   serviceVersion: S0007
   wireProtocol: CX_ORDERED_RELAY_2036_V1
   simulationProtocol: CX_SIM_30HZ_ORDERED_INPUT_439_V1
   tickRate: 30
7. Win11 Chrome 与 iPhone 11 Safari 两端均换成 S0007-0001-1 客户端，再匹配。

当前客户端连接地址沿用：
wss://cx-battle-match-relay.rosegun-chen.workers.dev/ws
如果部署到其他域名，需同步修改客户端 ONLINE_WS_URL。

服务端做什么：
- 匹配同规则、同部署档位的双方，分配阵营、共同随机种子。
- 收齐双方 Ready 时提交的战前配置，发送同一个开战时刻与双方配置。
- 将部署、战旗、输入完整性确认、稀疏检查点原样转发给对手。
- 不把操作发回发送者，不改写操作 Tick，不裁判单位、耗能、位置和胜负。
- 仍检查消息格式、协议及房间归属；这属于连接管理，不是战斗合法性校验。
- 断线、主动终止或房间过期时关闭本局。

与旧策略的区别：
本轮按最近商定的竞技停止规则执行；不接入旧的 10 秒转 AI 或断线恢复。
部署延迟必须早于该操作的敌方可见窗口安全边界，且不得达到 2 秒。
战旗单独采用自身的可见窗口。具体由客户端处理。

wrangler.jsonc 保留原 v1 SQLite Durable Object 迁移；没有新增迁移标签。
新联机房间使用新内部名称，避免混用旧协议房间。
旧客户端不支持新服务端的操作协议；正式验收时两端应一起换版。

回退：重新部署备份中的 S0006 服务端，同时两端恢复相应旧客户端。

版本命名更正：本包由上一交付包仅修改服务端版本号为 S0007；客户端对应 S0007-0001-1。
战斗规则、联机协议、记录协议与部署地址均沿用上一交付。package.json 版本对应调整为 0.7.0。
